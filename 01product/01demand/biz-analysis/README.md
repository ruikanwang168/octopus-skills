# biz-analysis

`biz-analysis` 用于把模糊业务想法、功能诉求或流程变化，梳理成经过确认的业务需求基线。

它重点验证：

- 用户遇到的真实问题、当前做法和根因；
- 期望结果和最小必要能力；
- 本期包含、不包含、保持不变和后续扩展的依据；
- 角色责任、主流程、关键异常和适用的兼容/依赖风险；
- 已确认事实、当前推测和待确认问题之间的边界。

输出形式不固定，可以是短文、结论清单、表格、流程图或组合。16 个分析维度只作为内部风险扫描池，不是固定问卷、固定章节或固定表格。

它不是 PRD、原型、数据库设计、接口设计或技术方案生成器。用户确认核心共识后，默认创建或更新 `需求梳理文档.md`；非阻塞待确认项可以保留在基线中，但必须说明影响。

## 使用节奏

1. 提取事实和用户观点，不重复询问材料已证明的内容。
2. 先判断是否存在正在使用的系统或流程，再路由为全新产品、增量迭代或小工具。
3. 把功能当作待验证假设，围绕场景、因果、反事实、结果、代价和边界深挖。
4. 每轮只问 2 到 4 个会改变业务判断的问题，并输出阶段性摘要。
5. 业务问题、必要能力、最小边界和关键风险闭环后，按项目选择最清楚的输出形式。
6. 通过内容质量校验后落盘，不以章节数量或 16 点覆盖率作为完成条件。
