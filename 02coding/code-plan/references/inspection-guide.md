# 渐进式物料与代码扫描

## 目录

- 扫描原则
- 第一层：物料与架构证据
- 第二层：业务关键词定位
- 第三层：模块目录取证
- 数据库证据
- 停止与提问条件
- 子代理回收格式

## 扫描原则

每次扫描只回答一个问题：项目是什么、使用什么技术、某个业务模块在哪里、某个接口或数据对象是否已存在。优先用文件列表和限定目录搜索，再读取少量命中文件。命中足够证据后停止。

禁止默认读取整个仓库、整个 PRD、所有接口或所有数据库模型。排除 `node_modules/`、`vendor/`、`.git/`、`dist/`、`build/`、`target/`、覆盖率目录、锁文件、压缩文件和生成代码。

## 第一层：物料与架构证据

先列出根目录两层内的文件与目录，并按来源记录：

| 来源 | 优先证据 |
|---|---|
| PRD/说明 | 目录、章节标题、业务流程、角色、范围、验收条件 |
| 原型 | 页面清单、路由、导航、表单字段、状态变化、页面间跳转 |
| 前端 | `package.json`、构建配置、入口、路由、状态管理、API 客户端目录 |
| Java 后端 | `pom.xml`、`build.gradle`、启动类、配置、Controller/Service/Mapper 目录 |
| Node 后端 | `package.json`、入口、路由、模块注册、ORM 配置、迁移目录 |
| Python 后端 | `pyproject.toml`、`requirements*.txt`、入口、路由、模型、迁移目录 |
| Go 后端 | `go.mod`、入口、路由、handler/service/repository、迁移目录 |
| .NET 后端 | `*.sln`、`*.csproj`、`Program.cs`、Controller、DbContext、迁移目录 |

只读取足以识别框架、目录约定和数据库驱动的片段。不要读取大体积锁文件来判断依赖。

## 第二层：业务关键词定位

从已确认模块提取 2 至 5 个稳定关键词：业务名、实体名、页面标题、路由片段或接口资源名。分别在前端和后端的高概率目录限定搜索。

按以下顺序缩小范围：

1. 路由和导航定位入口目录；
2. 页面或控制器定位模块目录；
3. API 客户端或服务定位接口所有权；
4. 模型、仓储或迁移定位数据对象；
5. 只在证据断裂时查看相邻引用。

搜索结果过多时增加目录、文件类型或精确词限制，不扩大为全仓内容输出。搜索结果为零时检查同义词、英文名和原型路由；仍为零则把模块标记为新增候选。

## 第三层：模块目录取证

每个业务模块最多需要形成下列目录级证据：

| 侧别 | 需要定位的目录 | 可选补充 |
|---|---|---|
| 单体 | 页面/模板、路由/控制器、业务服务、数据层 | 静态资源、测试 |
| 前端 | 页面或模块、组件、API 客户端、状态管理 | 路由、类型、测试 |
| 后端 | 路由/Controller、Service、Repository/Mapper、模型 | DTO、迁移、测试 |

同一职责分散在多个目录时全部列出，但不要继续枚举每个文件。计划只要求“在哪些目录开发”。

记录证据时使用：

```text
结论：订单管理前端沿用 src/modules/order/
证据：src/router/order.ts 引用该目录；src/modules/order/pages/ 已有列表页
计划影响：修改 src/modules/order/，补充 src/api/order/
置信状态：代码证据
```

## 数据库证据

优先查看数据库驱动、连接配置、ORM 配置、迁移工具、已有 DDL 和相关实体映射。不要因为开发环境出现 SQLite 文件就断定生产数据库也是 SQLite。

下列情况可直接沿用而无需用户选择：

- 构建依赖、连接配置和迁移方言相互一致；
- 相关模块已有表或迁移文件，且方言明确；
- 多环境使用同一数据库方言，仅连接地址不同。

下列情况必须询问：

- 配置支持多个不同数据库方言且无法确定目标环境；
- ORM 屏蔽了方言，但需要生成方言相关 DDL；
- PRD 要求新数据能力，而现有存储边界不清；
- 新系统的租户、ID、软删除或审计策略会改变所有表结构。

## 停止与提问条件

满足下列任一条件就停止扩大扫描：

- 技术框架和数据库已有两个相互印证的证据；
- 某模块的新增或修改目录已经唯一；
- 已确认相关接口或数据对象不存在，需要新增；
- 继续读取只会得到函数实现细节，不会改变计划目录或依赖。

遇到下列情况暂停并询问用户：

- PRD、原型和代码表达的业务范围互相冲突；
- 同一模块可能归属多个目录或服务，且选择会改变接口所有权；
- 存在多个活跃技术栈或数据库方言；
- 缺少决定接口字段、数据关系或权限边界的业务规则。

## 子代理回收格式

```md
## {业务域或扫描范围}

- 结论：
- 证据文件：
- 前端/单体目录：
- 后端目录：
- 接口与数据对象：
- 依赖：
- 冲突或缺口：
- 必须询问用户：
```

主代理只接收目录级结论和必要证据，不接收大段源码复述。
