# 增量模式规则

## 定位

增量模式只做一件事：同步代码事实和协作入口，不改用户手写规则，也不改用户维护的扫描忽略规则。

它用于项目已经跑了一段时间后，代码结构、技术栈、启动方式、测试方式、协作流程或工具入口发生变化，需要让 AI 规则文件重新跟上项目现状。

## 旧版布局迁移

判断新布局文件是否缺失前，先检查项目根目录的旧版 `PROJECT.md`、`USER_RULES.md`、`AI_IGNORE.md` 和 `AiCoder/` 目录：

- 旧版三个规则文件分别迁移到 `harness/PROJECT.md`、`harness/USER_RULES.md`、`harness/AI_IGNORE.md`。新路径不存在时，先沿用旧文件内容，不用默认模板覆盖；用户维护文件只改变位置，内容保持不变。
- 新旧路径同时存在时先比较内容；内容不同就列为冲突，不自动覆盖、合并或删除任一版本。存在忽略规则冲突时，先解决冲突再深度扫描源码。
- 迁移前先读取并应用已有忽略文件；迁移后匹配模式仍相对于项目根目录解释，不改变忽略范围。
- 旧版 `AiCoder/design/` 中的设计文档迁入 `harness/design/`，保留文件名和内容，遇到同名冲突不覆盖。
- 旧版 `AiCoder/prd/`、`AiCoder/task/`、`AiCoder/db/` 中的资料，只有能根据已有计划名、任务编号或文档引用确定计划归属和创建日期时，才原样归入 `harness/plan/YYYYMMDD-<计划标识>/`。归属或日期无法确认时保留原处，在摘要中列出待确认映射，不编造日期，不把不同计划合并或删除。
- 将迁移的源路径、目标路径及冲突列入写入前摘要。迁移后核对文件内容，并更新 `AGENTS.md`、`CLAUDE.md` 和项目快照中的引用；历史资料存在失效链接时列入待处理事项，不静默丢弃文件。

## 允许更新的内容

### 1. harness/PROJECT.md

`harness/PROJECT.md` 是增量模式的核心更新对象。

必须重新按 `project-template.md` 的源码检索要求扫描项目，并同步：

- 项目概述
- 核心技术栈（列表展示技术、版本、用途和技术红线，不附配置或来源）
- 主要目录职责（以目录树展示真实层级并标注职责与约束）
- 架构分层和模块边界
- 启动、构建、测试、格式化、检查命令
- 数据库、外部服务、第三方 SDK 等集成点
- 代码规范与常用命令
- 硬性规则（必须遵守）：根据实际项目约束形成包含适用范围、判定条件和检查方式的列表，不照搬参考示例。保留人工规则的范围、阈值和例外；缺少条件或与新技术栈冲突时列明待确认项，不补造门槛或改变人工规则的含义

如果旧 `harness/PROJECT.md` 与当前源码不一致，以源码和配置文件为准；无法确认的内容标为“待确认”。

重新扫描源码前，必须先读取并应用 `harness/AI_IGNORE.md` 或待迁移的旧版忽略文件；只有两者都缺失时，才按 `ai-ignore-template.md` 创建默认忽略模板，或在写入前临时采用默认忽略范围。

旧内容如何被修正，只写在增量摘要里；`harness/PROJECT.md` 正文保留当前项目事实和现行开发规则，不写“旧规则错误”“已移除旧描述”等过程说明。

### 2. AGENTS.md

`AGENTS.md` 是 Codex 入口，只同步协作 SOP，不承载项目技术细节。

可以更新：

- 角色边界和行动前确认规则
- “快速导航”表格：按扫描边界核对已有文件，补齐 `harness/` 下本次创建、迁移或已存在但漏记的文件；同步变更后的用途和路径，移除重复或失效记录，表头保持“你想做什么”“去哪里看”
- `harness/plan/YYYYMMDD-<计划标识>/` 的命名规则及其与 `harness/design/` 的读写边界
- 计划内 `需求.md`、`进度.md` 的用途、执行前读取要求，以及各次执行的任务 Markdown、数据库变更文件及其他文件的归档规则
- 需求编号、进度状态、验收依据及阶段完成、执行结束和交接前的进度更新规则
- 新功能和老功能修改时的文档同步要求
- 代码输出、安全命令确认、中文沟通等协作规则
- 提交规范及提交类型说明
- 文档元信息的生成、更新和扫描筛选规则；保留用户维护文件和原样迁移文件，不以缺少头部为由自动改写
- 对 `harness/PROJECT.md`、`harness/USER_RULES.md`、`harness/AI_IGNORE.md` 和工具入口文件的引用

不要把技术栈、目录清单、命令细节大段写入 `AGENTS.md`；这些内容应放在 `harness/PROJECT.md`。

`AGENTS.md` 必须保留规则优先级：`harness/USER_RULES.md` > `harness/AI_IGNORE.md` > `harness/PROJECT.md` > `AGENTS.md` > `CLAUDE.md`。

### 3. CLAUDE.md

默认同步维护 Codex 入口 `AGENTS.md` 和 Claude Code 入口 `CLAUDE.md`，不询问工具选择。

如果目标项目已经存在 `CLAUDE.md`，可以将其收敛为 `pointer-files-template.md` 中定义的短指针内容。

如果 `CLAUDE.md` 缺失，按同一模板创建，确保两个工具入口齐全。

### 4. 缺失基础文件

如果缺少以下基础文件，增量模式可以补齐：

- `AGENTS.md`
- `harness/PROJECT.md`
- `harness/USER_RULES.md`
- `harness/AI_IGNORE.md`

其中 `harness/USER_RULES.md` 只在新旧位置均缺失时创建占位，`harness/AI_IGNORE.md` 只在新旧位置均缺失时创建默认忽略模板；如果已有文件，只允许按迁移规则原样移动，不自动修改内容。缺少 `harness/plan/`、`harness/design/` 时补齐空目录，不创建计划业务文件。

## 禁止更新的内容

- 禁止自动修改或重写 `harness/USER_RULES.md`。
- 禁止自动修改或重写 `harness/AI_IGNORE.md`。
- 禁止在迁移时改写、删减或“优化”用户手写偏好。
- 禁止在迁移时改写、删减或“优化”用户维护的忽略列表。
- 禁止因为旧规则看起来不规范就覆盖用户手写内容。
- 禁止修改业务代码、配置文件、数据库脚本或项目源码；旧版计划资料只可按迁移规则原样移动，不改写内容。
- 禁止生成与源码事实无法对应的技术栈、命令或目录说明。

只有用户明确说“修改 harness/USER_RULES.md”或“把这条写入 harness/USER_RULES.md”时，才允许更新该文件。

只有用户明确说“修改 harness/AI_IGNORE.md”“把这个路径加入忽略”或“更新忽略列表”时，才允许更新该文件。

## 增量工作流

1. 扫描新布局的五个规则文件，并检查旧版布局，建立待迁移、待补齐和冲突清单；文档有效性按 `agents-template.md` 的元信息约定判断，不仅凭日期或缺少头部认定过期。
2. 读取并应用 `harness/AI_IGNORE.md` 或待迁移的旧版忽略文件；两者都缺失时，才将其列入补齐文件，并临时采用默认忽略范围。
3. 扫描项目源码和配置，重新建立项目事实，跳过 `harness/AI_IGNORE.md` 声明的忽略路径；扫描 Markdown 时先确认元信息，不把 `deprecated` 或未定稿内容直接当成现行项目依据。
4. 对比旧规则与当前项目事实，标记：
   - 保留：仍然准确且有价值的规则。
   - 更新：与当前代码不一致，需要修正的内容。
   - 补齐：缺失但必须存在的基础规则。
   - 冲突：不同规则文件之间互相矛盾，或规则与源码事实冲突。
   - 待确认：源码无法证明、需要用户确认的内容。
5. 先输出增量摘要，不直接静默覆盖。
6. 用户确认后再写入允许更新的文件、执行已列明的迁移，并补齐 `harness/plan/`、`harness/design/`；新生成的 Markdown 填写元信息，已获授权修改正文的文件同步实际更新日期，原样迁移文件不刷新日期。同步 `AGENTS.md` 的“快速导航”，登记本次新增或迁移的每个文件并更新变动路径。

## 输出摘要要求

写入前的摘要至少包含：

- 将更新的文件
- 将创建的缺失基础文件
- 将迁移的源路径、目标路径及仍待确认的旧资料归属
- 将创建的 `harness/plan/`、`harness/design/` 空目录
- `harness/PROJECT.md` 中会同步的代码事实
- `AGENTS.md` 中会调整的协作规则
- 将创建或更新的 Claude Code 入口 `CLAUDE.md`
- `harness/USER_RULES.md` 的处理方式：读取 / 原样迁移 / 新旧位置均缺失时创建占位
- `harness/AI_IGNORE.md` 的处理方式：读取并应用 / 原样迁移 / 新旧位置均缺失时创建默认忽略模板
- 待确认事项

写入后的摘要只保留：

- 已更新、创建或迁移的文件路径
- 已创建的 `harness/plan/`、`harness/design/` 空目录
- 主要更新点
- 未处理的冲突或待确认事项
