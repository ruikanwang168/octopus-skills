# 操作识别与覆盖检查清单

建立操作清单以及补充异常、边界、权限场景时读取本文件。清单只用于发现检查方向，不能替代 PRD、原型和代码证据。

## 四类物料提取

### PRD

- 提取业务范围、非范围、用户角色、主流程、业务规则、验收标准、字段定义、状态流转、错误提示、权限矩阵和发布约束。
- 使用章节编号、需求编号或验收标准编号作为需求来源。
- 标记每个条目是新增、变更、删除/下线，还是未变更背景；PRD 没写但代码中存在的背景行为不能被忽略。

### 可运行原型

- 记录页面和路由、入口、菜单、按钮、链接、表单、列表、弹窗、抽屉、页签和批量操作。
- 实际触发操作，观察默认值、禁用状态、二次确认、成功反馈、失败反馈、空态、加载态和跳转结果。
- 对每个静态路由记录访问结果：已访问、需要账号、运行阻塞或不存在。
- 不把单纯的点击、输入或页面跳转自动视为独立测试目标；检查它是否存在独立规则和可观察结果。

### 前端代码

- 检查路由与守卫、组件事件、表单规则、按钮显示条件、状态管理、缓存、接口参数、错误处理和重复提交保护。
- 搜索 `onClick`, `onSubmit`, `emit`, `dispatch`, `navigate`, `router`, `validate`, `request`, `api` 等项目实际使用的事件和调用模式。
- 将隐藏操作、快捷入口和条件渲染与原型中的可见行为对照，记录不一致。

### 后端代码

- 检查 controller/router、DTO/schema、service、权限中间件、状态机、repository/model、事务、唯一约束、幂等、消息和第三方调用。
- 追踪前端调用到对应接口，提取请求参数、响应、错误码、权限、业务校验、状态变更和数据写入结果。
- 将后端存在但 PRD 未说明的约束标记为实现依据或待确认，不要自动上升为产品需求。

## 变更与回归识别

- `新增`：PRD 明确新增且原型出现的页面、操作、规则或接口；即使现有代码尚未实现，也要生成目标用例。
- `变更`：现有代码已有对应能力，但 PRD 或原型改变了流程、字段、权限、状态、提示或接口契约。
- `受影响回归`：未被 PRD 直接标记，但复用了变更后的组件、路由、API、服务、权限、状态、模型、消息或配置的旧操作。
- `删除/下线`：PRD 或原型移除现有入口、操作或状态；至少验证不可见、不可调用和历史数据影响。
- `冲突/待确认`：PRD、原型、前端或后端结论不一致；不得静默合并。

## 独立操作判断

为满足以下任一类别且具有独立可观察结果的目标建立 `OP-xxx`：

- 用户目标：新增、查询、编辑、删除、提交、撤回、审批、取消、导入、导出等。
- 独立规则：必填、格式、唯一性、额度、时间、跨字段依赖、重复提交等。
- 权限差异：角色可见性、按钮可用性、接口鉴权、数据隔离和越权访问。
- 状态流转：草稿、提交、通过、驳回、取消、过期、归档和重新打开。
- 接口或数据结果：落库、幂等、事务回滚、消息发送、回调和第三方同步。

以下内容通常作为步骤而不是独立用例：进入页面、聚焦输入框、逐字段输入、普通翻页、关闭无业务规则的弹窗。只有它们存在独立规则、风险或反馈时才拆分。

## 操作清单字段

至少记录：

- 操作标识：`OP-001`、`OP-002`。
- 变更类型：新增、变更、受影响回归、删除/下线或冲突/待确认。
- 所属模块和页面/接口。
- 操作名称与用户目标。
- 角色、入口和前置状态。
- 输入或触发条件。
- 可观察的界面、接口和数据结果。
- 来源证据：PRD 章节、原型路由/运行记录、前端文件和后端文件。
- 证据级别：`明确需求`、`规则推导`、`实现现状`、`运行验证`、`待确认`。

## 用例覆盖维度

- 正向：每个独立操作至少一条成功或允许执行的用例。
- 分支：可选输入、替代入口、不同角色、重复操作和部分完成。
- 校验：必填、长度、格式、唯一性、非法字符、数值范围、日期范围和跨字段依赖。
- 边界：最小/最大值、空数据、单条/大量数据、分页边界、文件限制、时间边界和精度。
- 异常：网络失败、服务端错误、超时、重复提交、脏数据、会话过期和依赖不可用。
- 权限：未登录、无角色权限、数据越权、按钮隐藏但接口可调用、权限过期和审计记录。
- 状态：允许流转、禁止流转、重复流转、不可逆流转和并发状态变化。
- 数据：刷新后持久化、并发编辑、幂等、去重、事务回滚以及页面与接口一致性。
- 集成：请求参数、响应映射、重试、回调、消息、第三方错误和向后兼容。
- 非功能：只有物料给出阈值、支持范围或明确风险时，才生成性能、兼容、安全和隐私用例。

## 拆分检查

- 一条用例只写一个可独立失败的测试目标，不等于只能写一个操作步骤。
- 同一操作的正向、不同校验规则、权限差异和关键状态分别建立用例。
- 多个操作组成端到端核心流程时，可以补充流程用例，但不能替代每个独立操作的基础用例。
- 不为没有独立预期的每次点击机械生成用例。
- 不合并结果互不相关、失败后需要分别定位的检查点。

## 最终检查

- 操作清单中的每个 `OP-xxx` 至少关联一条正向用例，或记录未覆盖原因。
- 每个 PRD 新增/变更点和每个原型可达独立操作都有用例，或记录未覆盖原因。
- 共享依赖影响到的旧功能有回归用例，或有代码证据说明不受影响。
- 测试人员无需阅读源码也能按步骤执行。
- 预期包含具体界面、接口或数据结果，不使用“正常”“正确”“符合预期”。
- PRD、原型、前端和后端之间的冲突已单独列出。
- 实现现状、规则推导、运行验证和待确认内容没有伪装成同一种证据。
